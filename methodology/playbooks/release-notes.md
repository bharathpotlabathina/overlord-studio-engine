# Runbook — Release notes

Owner: Release Engineer. Audience-first: notes are for the CLIENT/operator, not
the git log.

1. Three sections, plain language: **What's new** (user-visible, benefit-phrased) ·
   **What changed** (behavior differences an operator will notice, incl. anything
   removed) · **What to do** (any action the client must take; "nothing" is a
   valid and common answer).
2. No internal jargon, no codenames, no file paths, no roadmap IDs. Client-facing
   names only.
3. Version-stamped (see release-version.md). One page maximum.
4. The Director reviews notes before they leave the studio (client-facing artifact
   = his voice, his call).
